# 🚦 V2X Smart Traffic Coordination System

An end-to-end Python project that simulates smart traffic conditions, predicts the next traffic-density value using machine learning, and presents the results through an interactive Streamlit dashboard.

> **Project status:** Learning and portfolio demonstration  
> **Data source:** Synthetic traffic data generated by this project  
> **Important:** This is not connected to live roads, vehicles, roadside units, or traffic signals.

---

## 📌 Project Overview

Traffic congestion can increase travel time, fuel use, and delays for emergency vehicles. This project demonstrates how traffic data and a machine-learning model could support traffic monitoring and decision-making in a simulated environment.

The system generates sample traffic records, trains a regression model to estimate the next recorded traffic-density value, and displays the results in a dashboard with scenario controls, charts, alerts, and an illustrative map.

## 🎯 Project Objectives

- Generate repeatable synthetic traffic data for experimentation.
- Explore the relationship between vehicle count, traffic density, and average speed.
- Train and evaluate a Random Forest regression model.
- Compare model performance with simple baseline predictions.
- Visualize traffic patterns and model predictions in Streamlit.
- Demonstrate the concept of V2X (Vehicle-to-Everything) communication using clearly labelled simulated scenarios.

## ✨ Key Features

| Feature | Description |
|---|---|
| Traffic simulation | Generates timestamped traffic records with vehicle counts, density, speed, signal state, emergency status, and congestion category. |
| Scenario controls | Switch between Normal, Rush Hour, and Emergency Vehicle scenarios. |
| Machine learning | Predicts the traffic-density value for the next record using a trained Random Forest model. |
| Model evaluation | Reports MAE and RMSE and compares the model with simple baselines. |
| Interactive dashboard | Displays traffic metrics, trend charts, congestion distribution, and sampled traffic relationships. |
| Illustrative intersection and map | Shows concept visuals for traffic monitoring; these are not live vehicle locations or routes. |
| Data export | Downloads the generated traffic dataset as a CSV file. |

## ⚙️ Installation and Setup

### 1. Requirements

Install Python 3.10 or later and Git if you plan to clone the repository. Use a terminal opened in the project folder.

### 2. Get the project

If you have already downloaded or cloned the repository, open that folder in VS Code and skip this step.

```powershell
git clone https://github.com/vrshy/V2X-Smart-Traffic-Co-Ordination-System.git
cd V2X-Smart-Traffic-Co-Ordination-System
```

### 3. Create and activate a virtual environment

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

If PowerShell blocks activation, you can run the environment's Python directly using `.\.venv\Scripts\python.exe` in the commands below.

### 4. Install dependencies

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### 5. Generate the traffic dataset

```powershell
python simulation.py
```

This creates `data/traffic_data.csv`.

### 6. Train and evaluate the model

```powershell
python train_model.py
```

This prints evaluation metrics and saves the trained model to `models/traffic_model.pkl`.

### 7. Launch the dashboard

```powershell
streamlit run app.py
```

Streamlit will display a local URL in the terminal, usually `http://localhost:8501`. Open that address in your browser if it does not open automatically.

## 🧠 Machine-Learning Workflow

1. **Generate data:** Create timestamped synthetic traffic observations.
2. **Prepare features:** Convert timestamps and signal states into numerical model inputs.
3. **Create target:** Use the next record's traffic density as the prediction target.
4. **Split chronologically:** Use earlier records for training and later records for testing.
5. **Train:** Fit a Random Forest Regressor.
6. **Evaluate:** Compare MAE and RMSE against simple baselines.
7. **Visualize:** Display a prediction for the selected simulated scenario in the dashboard.

### Model evaluation

- **MAE (Mean Absolute Error):** Average absolute difference between predictions and actual values. Lower is better.
- **RMSE (Root Mean Squared Error):** Error metric that penalizes larger errors more strongly. Lower is better.

The project compares the Random Forest model with a training-mean baseline and a carry-forward baseline. A more complex model is not automatically better: review the printed results to determine whether it improves on the baselines. Do not claim a performance improvement unless your own run demonstrates it.

## 📊 Dashboard Guide

The dashboard includes:

- **Traffic metrics:** Vehicle count, traffic density, average speed, signal status, and congestion level.
- **Scenario selector:** Applies simple illustrative adjustments for normal traffic, rush hour, or an emergency vehicle.
- **Traffic trend:** Displays recent simulated density values.
- **Prediction panel:** Shows the model's next-record density estimate.
- **Congestion distribution:** Summarizes the generated dataset's congestion categories.
- **Traffic relationship chart:** Compares vehicle count and average speed.
- **Intersection and map visuals:** Concept illustrations using a fixed demo location.
- **CSV download:** Exports the traffic records for further analysis.

## 🔍 Limitations and Future Improvements

### Current limitations

- The dataset is synthetic, not collected from real traffic sensors.
- The model predicts the next record in this generated dataset; it is not a validated city-wide traffic forecast.
- Emergency handling, signal behavior, vehicle positions, and map overlays are simulated.
- The displayed map does not show live traffic, live GPS positions, or actual emergency routes.
- Results depend on the simulation assumptions and should not be interpreted as real-world performance.

### Possible future improvements

- Test the model on a real, documented traffic dataset.
- Add predicted-versus-actual plots and save evaluation results to CSV.
- Explore time-series forecasting and compare it with the regression baseline.
- Add congestion classification and traffic-pattern clustering.
- Test whether model errors differ between traffic scenarios.
- Add unit tests, input validation, and a reproducible experiment report.
